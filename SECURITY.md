# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выходят патч-релизом (`vX.Y.Z`) для последней минорной ветки.
Рекомендуется использовать конкретный тег или digest, а не `latest`.

## Как сообщить об уязвимости

Не открывайте публичный issue. Используйте приватный канал GitHub:
**Security → Report a vulnerability** (Private vulnerability reporting) в этом репозитории.

Опишите: версию образа/коммит, воспроизведение, ожидаемое и фактическое поведение, оценку влияния.
Мы подтвердим получение и вернёмся с оценкой и планом исправления.

## Модель угроз (кратко)

- `/v1/*` — **внутренний API** без аутентификации: не публикуйте порт наружу, вызывайте по
  внутренней docker-сети (см. README, раздел про nginx). Rate-limit — на вашей стороне.
- `/tiles/*` и `/example` — публичные; `/example` можно выключить (`ENABLE_EXAMPLE=false`).
- Встроенный PostgreSQL слушает только `127.0.0.1` внутри контейнера; приложение работает
  от непривилегированного пользователя, `serve` ходит в БД ролью только на чтение.
- Данные (PBF) скачиваются только по `https` (http — для локальных зеркал) с проверкой
  целостности формата; содержимое PBF не исполняется.
- Образ собирается из закреплённых базовых образов; в CI — `govulncheck`, при публикации —
  SBOM и provenance.

Известные ограничения (осознанные):

- Полнота данных и их актуальность зависят от выбранного PBF-источника.
- Атрибуция `© OpenMapTiles · © OpenStreetMap contributors` обязательна при использовании карты.
