## [Unreleased]

Исправления по итогам аудита лицензий и поведения образа `v0.1.4`.

### Fixed

- **`UPDATE_SCHEDULE` не обновлял данные.** Планировщик работал внутри `serve` ролью `geo_reader`
  и каждый запуск падал с `permission denied for schema public`. Теперь расписание выполняет
  отдельный процесс `slup-geo schedule` с правами `update` (`geo_owner`); entrypoint запускает его
  при заданном `UPDATE_SCHEDULE`, `serve` по-прежнему только читает БД.
- **Поиск по белорусским названиям.** Нормализация (Go и `geo.names`) выбрасывала `і`/`ў`
  (и украинские `ї`/`є`/`ґ`) как пунктуацию: «вуліца Міцкевіча» превращалась в «вул ца м цкев ча»,
  а снятие типового слова «вуліца» не срабатывало. Версия схемы — `2`: после обновления образа
  выполните `slup-geo update` (или дождитесь расписания / `UPDATE_ON_START`).
- **Обновление тайлов и открытые карты.** `basemap.pmtiles` и версионные файлы отдаются с `ETag`
  (клиент pmtiles замечает смену архива); предыдущая версия тайлов хранится до следующего
  обновления — закешированные `immutable`-ссылки не дают 404 сразу после публикации.
- **Версия схемы пишется после swap.** `geo.meta.schema_version` больше не обновляется на этапе
  staging: сбойная замена не оставляет «новую» версию над старыми данными.
- **Атрибуция в `tiles.json`.** Манифест (и пустой манифест по умолчанию) содержит
  `© OpenMapTiles · © OpenStreetMap contributors`, а не только OSM.
- **Лицензии в образе.** В образ попадают `LICENSE` (раньше исключался `.dockerignore`),
  `THIRD_PARTY_LICENSES.md`, тексты лицензий стандартной библиотеки Go и всех Go-модулей,
  уведомления библиотек, вкомпилированных в tilemaker (MIT/BSD/ISC/Apache-2.0/BSL-1.0), и
  список точных версий пакетов Debian/PGDG — по нему находятся исходники GPL-компонентов.
  Для вендорных MapLibre GL JS и pmtiles JS добавлены файлы лицензий.
- **`THIRD_PARTY_LICENSES.md`.** Исправлены пути профиля tilemaker и лицензия схемы OpenMapTiles
  (код BSD-3, схема/дизайн CC-BY 4.0); описаны ODbL для тайлов и ответов API, источники
  исходников GPL-пакетов, состав tilemaker.
- **Мелочи.** `/v1/point` не пишет координаты в лог ошибок (как и access-лог); из образа убраны
  неиспользуемые `libboost-iostreams`/`libboost-system`; `TestIsWritable` пропускается под root.
- **CI: `govulncheck`.** Go обновлён до `1.27.2` (базовый образ сборки — по новому диджесту):
  в `1.27.0` govulncheck находил уязвимости стандартной библиотеки `net/http` и валил
  обязательный чек `test`.

### Changed

- Новая команда `slup-geo schedule`; `serve` больше не запускает cron. При внешней БД без
  entrypoint образа запускайте `slup-geo schedule` отдельным процессом.
- CI: интеграционные тесты — на `postgis/postgis:16-3.5`, закреплённом по digest (3.6 для PG16
  не публикуется); новый job `e2e` собирает образ и прогоняет `scripts/ci-e2e.sh` на PBF Монако
  (первый импорт, тайлы, атрибуция, обновление по расписанию, лицензии в образе) — публикация
  ждёт его. Изменение `THIRD_PARTY_LICENSES.md` и `LICENSE` теперь пересобирает образ.

## [0.1.4] — 2026-10-07

### Fixed

- **Короткий swap вместо долгой блокировки.** Матвью новой генерации собираются заранее под
  именами `geo.*_next` вне транзакции (читатели не блокируются), финальная замена — только
  `DROP`/`RENAME` метаданных: окно блокировки сократилось с десятков секунд до долей секунды.
- **`UPDATE_ON_START` не останавливает сервис.** При готовой схеме обновление идёт фоном, `serve`
  стартует сразу на прежних данных; провал первого импорта завершает контейнер с кодом 1 —
  restart-политика повторяет попытку вместо вечного `503 no_data`.
- **Админ-пароль недоступен приложению.** `env -u POSTGRES_PASSWORD` для serve/update, файл
  `db_password` остаётся root-only, локальные подключения к PostgreSQL требуют пароль (scram) —
  роль-модель `geo_reader`/`geo_owner` энфорсится.
- **Незавершённый статус.** После жёсткого останова `status.json` со `state=running` помечается
  как прерванный (проверка по advisory lock) — `/health` не зависает в `starting`.
- **PBF.** Ошибки санитизируются (userinfo/query маскируются), `PBF_URL` с кредами не попадает
  в логи и `/status`; read-only `PBF_PATH` используется как есть без тройной перезагрузки.
- **Атрибуция.** Добавлена в метаданные PMTiles (`settings.metadata.attribution` — tilemaker
  читает только этот ключ) и в `source.attribution` стиля.
- **CI/инфра.** `govulncheck` закреплён по версии; публикации в Docker Hub сериализуются
  (`concurrency`) — больше нет гонки за `:latest`; интеграционные тесты покрывают и swap.
- **Мелочи.** Алиас `basemap.pmtiles` не отдаёт каталог с подходящим именем; кэш вендорных
  модулей — сутки; README: порт в quick start и честное описание окна переключения;
  `docs/publishing.md` удалён (тексты перенесены в задачу).

## [0.1.2] — 2026-10-07

Исправления по итогам независимого security/usability-аудита.

### Fixed

- **Неразрушающее обновление.** Импорт идёт в staging-таблицы `planet_osm_next_*`; замена рабочих
  таблиц и пересборка представлений — одной транзакцией. Сбой на любом шаге (битый PBF, диск, OOM)
  больше не оставляет API без данных: старые таблицы и тайлы продолжают работать.
- **Честный `/health`.** Проверяет не только ping БД, но и готовность представлений geo:
  `starting`/`no_data` (503) вместо ложного `ok`; в ответе `importedAt` и последний статус
  обновления. Добавлен `GET /status` (данные + `status.json`).
- **Жизненный цикл контейнера.** Entrypoint возвращает код упавшего процесса (`restart: on-failure`
  работает), пробрасывает SIGTERM в `update`, понимает `1/yes/on` в `UPDATE_ON_START`, чистит
  `.part`-файлы, пишет пароли с правами `600`.
- **Загрузка PBF.** Только `https` (http — для локальных зеркал), запрет небезопасных редиректов,
  лимит размера, проверка полноты (`written == Content-Length`) и заголовка PBF до импорта;
  при сбое сети — работа на локальном валидном кэше. URL с кредами редактируется в логах и `state.json`.
- **Права БД.** `geo_owner` — владелец данных для `update` (без суперправ), `geo_reader` — только
  `SELECT` для `serve`; `geo_user` остаётся администратором и приложением не используется.
  PostgreSQL слушает только `127.0.0.1`. Приложение работает не от root (пользователь `slup`).
- **HTTP-устойчивость.** `Read/Write/Idle` таймауты, `MaxHeaderBytes`, `statement_timeout` в БД,
  лимит длины `q` (128), валидация `simplify` (неизвестное значение — 400), запрет `+` в id.
- **Заголовки и логи.** `X-Content-Type-Options`, `Referrer-Policy`, CSP для `/example`,
  access-лог (без query).
- **Зависимости.** `x/text` обновлён; MapLibre GL JS обновлён до 6.12.0 (ESM, закрыта XSS
  в attribution), вендорные библиотеки переехали в `/tiles/vendor/*` (доступны и при
  `ENABLE_EXAMPLE=false`).
- **Supply chain.** Базовые образы закреплены по digest, sha256 для архива tilemaker, Actions —
  по commit SHA, Dependabot, `govulncheck` в CI, SBOM/provenance при публикации,
  сборка `linux/amd64` + `linux/arm64`.
- **CI.** Интеграционный тест SQL-схемы и `PGStore` на живом PostGIS (фикстура
  `scripts/ci-fixture-planet.sql`).
- **Документация.** Полный список ENV (`WEB_DIR`, `SHUTDOWN_TIMEOUT_SECONDS`, `POSTGRES_*`, `TZ`…),
  nginx-пример, sizing и пиковый диск на время обновления, cron 5 полей и таймзона, ручное
  обновление, FAQ и сравнение с альтернативами; compose-пример с hardening
  (`deploy/compose.example.yml`).

### Changed

- Тайлы публикуются после успешной замены таблиц БД; манифест `tiles.json` пишется до удаления
  старых файлов и содержит только актуальный файл; алиас кэшируется 60 с, глифы — сутки.
- В `state.json` добавлен `schemaVersion`; появился `status.json` (статус последней попытки).
- `/v1/areas` для адресов-нод (`N…`) отдаёт `Point` — так и было, теперь это описано в openapi.
- В `Suggestion` дедуплицируются N и W одного адреса; формат имени дома в `/areas` совпадает
  с `/point` и `/suggest`.
- Стиль карты: абсолютные пути (`/tiles/...`) — исправлена формулировка в README (для подпути
  нужна правка путей).
